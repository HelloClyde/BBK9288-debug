# 9288 Debug v0.2.0（实验预发布）

把先前独立 D88REF 工具中的固件重扫程序列表能力集成到驻留 Debug，无需另装刷新工具。

- 新增电脑按钮和 CLI `refresh-apps`，在原生 GUI1 中检查固件指纹、桌面状态后调用原生扫描器，再排队重绘。
- GUI 默认勾选程序上传后刷新，仅适用于 `A:\系统\程序\*.exe`；CLI 上传可显式加 `--refresh-apps`。
- 上传提交与刷新分别报告。刷新失败不会重传文件或回滚已提交的上传；扫描开始后发生错误时，明确提示可能已部分执行。
- 文件事务未结束或设备未回到原生桌面时返回忙；执行前取消不扫描，执行中取消保留实际结果，不自动重放。

仅适配已经核对的原版 9288 固件。旧服务没有新能力位，需更新机端程序并正常重启，再运行 D88DEBUG 到 READY；仅更新 Windows 客户端不会增加机端能力。USB 线可一直插着供电。

下载 `BBK9288-debug-0.2.0-windows-x64.zip`，设备文件在 `device/系统/程序`，Windows 客户端在 `pc`；SHA-256 清单覆盖四项交付文件，安装包内还有逐文件清单与第三方许可证。

新版运行时与 v0.1.0 不同，验证按本次映像和载荷摘要绑定，详见 `docs/runtime-validation.json`、`docs/app-refresh.md` 和资产 `build-report.json`。仓库及 Release 不包含固件、NAND、SDK、工具链或用户数据。

本次实际验收：302 项测试中 296 项通过、6 项私有固件对照跳过；原生 GUI1 模型与新版真机均通过刷新、事务互斥和重复扫描验证。真机实测程序上传后分类缓存立即更新，原诊断文件及分类随后完整恢复，三次普通重连后错误数仍为 0。STOP/磁盘恢复和长期空闲恢复未重新进行物理机验收。
