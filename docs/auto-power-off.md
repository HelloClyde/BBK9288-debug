# 后台调试与自动关机

历史 `f156bf41` 版本已经在真机完成 USB 枚举、截图、按键和 RAM 操作，但后台运行仍会遇到原生自动关机。本轮 `d7af4f73` 增加空闲计时刷新，已通过生产 C、原生内核及下述真机静置验证。

## 原因

捕获固件的原生 MSC 在处理 SCSI `READ_CAPACITY`（`0x25`）后设置会话标志 `024EF018`。电源定时中断 `02198A28` 通过 `0219C1EA` 读取该标志；非零时先清空闲计数 `024EEF54`，随后再递增，使计数无法积累到原生阈值。退出原生磁盘模式会清除会话标志。

CDC 调试服务不处理 MSC 命令，因此 USB 供电和通信本身不会建立这项保护。该标志还参与其他原生退出和电源分支，不能用伪造 MSC 状态来保活。

## 有限刷新方案

`power_idle.c` 核验 GUI 根指针、捕获 GUI 表 `021E7B54 + 064C` 的入口和函数的 10 字节签名后，调用原生 `02198C94`。该无参数叶函数只将 `024EEF54` 清零后返回。SDK 尾部布局与该固件不兼容，不能按 SDK 的 `ResetAutoCloseTimer` 成员偏移调用。

- `begin` 在短 CPU 锁内检查待处理关机标志 `02049684`；非零则拒绝启动保活，保留原生请求，不清标志。确认可启动后复位计数并激活刷新。
- `RUNNING` 期间周期调用 `poll` 刷新；每次验证失败即停止保活并报告错误。周期不依赖对真实分钟频率的猜测。
- 停止或失败清理时调用 `end`，停止后不再清计数。原生从最近一次刷新后继续累计；不会恢复开始调试前已经过去的空闲时间。

该方案保留用户配置的关机分钟数、MSC 会话标志及其他 GUI 定时器，不发送伪造按键，也不永久关闭自动关机。原生 USB UI 另外采用过整组 GUI 定时器暂停/恢复，后台调试不复用该全局暂停方式。

## 验证范围

131 项自动测试通过。生产 C 模型覆盖三倍超时间隔内持续保持、`end` 后恢复累计并过期，以及已有待处理关机请求、指纹变化和锁错误时拒绝刷新。原生 ROS 集成通过两轮启停：实际原生复位函数把测试种入的低计数清零，停止后不再清除；用户设置、MSC 标志和 GUI 计时器暂停标志保持不变。该种值位于过期阈值以下，属于明确的测试输入，模型结果不能替代真机长期运行验收。

2026-11-05，真机原始关机设置读回为合法值 5 分钟。在关闭串口客户端后，以电脑单调时钟记录 331.078 秒无 agent RPC、按键、写入或 STOP 的静置间隔，USB 线持续连接供电。重新打开 COM3，严格身份、image_id、驻留基址、函数指针和 starts=1 均匹配；polls 增加 53075，计时复位次数增加 6635，保护保持 active=1、last_error=0，空闲计数仍为 0，原设置仍为 5。MSC 标志、GUI 计时器暂停标志和待处理关机请求均为 0。

随后取得 320×240 灰度真机截图，最终 181 次协议请求、0 错误，快照已释放，服务继续运行。证据保存在本地 `captures/2026-11-05-keepawake-physical/acceptance.json` 及 `screen-after-idle.png`；这些采集文件不随开发包分发。该结果验证了此设置下超过关机时限的后台运行，不扩展为任意时长、任意配置或 STOP 后恢复的物理验收。
