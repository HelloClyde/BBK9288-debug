# 9288 内存实测

`D88MEM` 是独立下载程序，配合现有 `D88DEBUG` 读取报告；它不替换驻留调试器。当前目标为已采集的 `CAPTURED-0215EBC4` 固件。真机容量和速度结果应绑定 `dist/memory-build.json` 中的 image_id、SHA256 及当次报告，不能用 QEMU 速度代替。

## 早期只读快照（历史）

2026-11-05，早期通过严格握手的 COM3 读取两组完全相同的堆状态和目录：系统原生堆为 `02500000..02700000`，共 2 MiB。桌面和 `d7af4f73` 调试器运行时，连续最大候选为 1,764,784 字节（约 1.683 MiB），推算总可用 payload 为 1,765,932 字节。当时只是只读估算，未实际申请；最终真机分配与速度结果见下方“2026-11-05 真机实测”。两轮运行的调试器和堆占用不同，不能把这个早期候选当作本轮实际申请上限。

官方 [S1C33L05 手册](https://www.epson.jp/prod/semicon/pdf/id000446.pdf) 列出 16 KiB 片内 IRAM 和 40 KiB IVRAM。捕获固件的 SDRAM 初始化配置对应 8 MiB、四个各 2 MiB 的内部 bank；D88MEM 会读取当前控制器配置后再解释这些地址。`02400000` 不是 BCU 区域边界。控制器组织、芯片内部 bank 与实际物理封装数量是不同概念，不能由“前后两段地址”断言两颗不同速 RAM。

## 测试方法

- 最大块：同一短 CPU 锁中核对原生分配器和完整目录，申请当前最大候选并立即释放，再测试最大值加 1 的失败边界。保存并恢复 errno，比较五个堆全局和有效目录。它不清零或填充整个最大块。
- 写入缓冲：另行申请最多 1 MiB，并保留至少 128 KiB 总量和连续 GUI 余量；所有写入和复制均限制在这个独占块内。实际地址决定被比较的 bank，不向固定未分配地址写入。
- 读取：相同原生循环、相同 16 KiB 工作集，比较 IRAM、正在供 LCD 使用的 IVRAM，以及四段 SDRAM。代码始终位于下载窗口的 SDRAM，测试包括指令读取和实际中断干扰，不代表裸存储器的理论峰值。
- 写入和复制：64 KiB 工作集。复制前将源设为非恒定图案、目标设为反码；写入和复制完成后逐字核对，准备和核对不计入测速时间。
- 每项三轮，中间一轮逆序，记录各轮原始字节数、RTC ticks、ROS ticks 和 Timer2 状态。每轮四个连续窗口，每窗口至少 32 个 RTC ticks，窗口之间主动让出 CPU，使后台 USB 和防关机任务继续运行。显式等待不计入各项时间，中断抢占包含在内。

RTC 读取为纯只读、跨进位复核的二进制秒/分/分频计数。名义 256 Hz 来自 OSC1/128，未经独立频率核对前，只能给出基于此频率的近似 MiB/s。四窗口共至少 128 ticks，累计端点量化误差上界约 4 ticks（约 3.1%），另有晶振和中断影响。复制速率按 payload 计一次，不把读加写双倍流量冒充 payload 带宽。

## 构建和采集

```powershell
python build_memory.py
python -m host.memory --port COM3 --output captures/memory-run
```

将 `dist/9288MemoryProbe.exe` 安装到设备 `系统/程序`。退出 USB 磁盘后先运行 D88DEBUG，再运行 D88MEM；确认 START 后开始，DONE 时保持界面供电脑读取。8192 字节报告位于程序自己的下载窗口，带 image_id、区段边界和 CRC32，保存为电脑上的 `D88MEM.BIN`、`acceptance.json`。报告完成前已释放测试块；若完整性检查失败，则报告错误并停止进一步分配器写入。

测试程序、真实内核 smoke、主机解码和实际硬件的验证范围见 `dist/memory-validation.json`。独立 NAND 和私有固件不随开发包分发。

## 2026-11-05 真机实测

使用 D88DEBUG `f9dc2295` 和 D88MEM `c97200b8`。30 项结果全部完成，报告为 DONE、result=0、flags=31，8192 字节报告的 CRC32 为 `dab74472`。文件传输、菜单按键和测试程序启动均通过实际 USB 调试通道完成，没有把 USB 传输耗时当作内存速度。

当前 SDRAM 控制器配置为 **8MiB、4 个内部 bank，每个 2MiB**；原生 malloc 管理的堆仅为 `0x02500000..0x02700000`，共 **2MiB**。本轮在调试器驻留、原生界面运行的状态下，实际申请 **1,733,036 字节（1.652752MiB）成功**，申请 1,733,037 字节返回空指针。申请后立即释放，errno、堆状态和有效目录均恢复；这是真实 malloc 边界，不只是根据空闲指针估算。该上限依赖当前已用内存和碎片，并非任意程序永远可用的固定容量。

测速另申请 1MiB 工作块 `0x02558C44..0x02658C44`，A 窗口为 `0x02560000..0x02570000`（bank2），B 为 `0x02600000..0x02610000`（bank3）。所有写入/复制仅触及自有内存；完成后工作块已释放，`heap_before == heap_after`，有效目录 CRC32 均为 `d074e75e`。

下表为每项三次测量的中位值。读取使用同一 16KiB 循环，写入/复制使用 64KiB 窗口；单位是 **MiB/s**。

| 操作 | 地址或方向 | 中位速度 |
|---|---|---:|
| 片内 IRAM 读取 | `0x00000000` | 9.906 |
| 片内 IVRAM 读取，LCD 开启 | `0x003C0000` | 6.438 |
| SDRAM bank0 读取 | `0x02010000` | 5.313 |
| SDRAM bank1 读取 | `0x02210000` | 5.344 |
| SDRAM bank2 读取 | `0x02410000` | 5.313 |
| SDRAM bank3 读取 | `0x02610000` | 5.313 |
| SDRAM A 写入 | bank2 | 5.333 |
| SDRAM B 写入 | bank3 | 5.333 |
| SDRAM 复制 | A → B | 3.631 |
| SDRAM 复制 | B → A | 3.631 |

四个 SDRAM bank 的读取中位值最大差约 **0.59%**；A/B 写入及双向复制的中位值一致，本轮没有发现明显的外部 SDRAM 快慢分区。片内 IRAM 读取约为 SDRAM 的 **1.86 倍**，IVRAM 约为 **1.21 倍**。这里的内部 bank、两个工作窗或映射使能位不能证明存在两颗物理 RAM 芯片；本轮没有拆机确认封装数量。

速度按设备 RTC 的**标称 256Hz**计算，未做外部精密频率校准。全轮 RTC 为 28.707 秒，电脑从首见 RUNNING 到 DONE 为 29.016 秒，仅作量级核对。显式让出 CPU 的时间被扣除，中断、循环及校验累加的开销包含在内；这些是该原生测试循环的近似吞吐率，不是裸内存总线峰值。复制按有效载荷计算一次，也未测 malloc/free 本身的延迟。

本地完整证据位于 `captures/2026-11-05-memory-physical/`：`D88MEM.BIN` 的 SHA256 为 `13648925f00a6e4332e829ac41975b325ec86ddd60ec5b45c85acd9526753a76`，`acceptance.json` 保存每轮原始字节数及计时数据。报告和截图已读回后，设备返回菜单，后台调试服务继续运行；最终状态及截图见同目录 `final-device-state.json`、`menu-restored.png`。采集目录不随开发包分发，汇总与摘要保存在 `dist/memory-validation.json`。

## 8MiB 的去向，以及程序如何使用更多

8MiB 是当前外部 SDRAM 的配置容量。系统 malloc 只管理固定的 2MiB 池，原生启动代码在 `0x0215ED52..0x0215ED62` 向分配器传入边界，最终对齐为 `0x02500000..0x02700000`。其余 SDRAM 按固件布局使用或保留。下列地址均为左闭右开范围。

| SDRAM 范围 | 大小 | 已核实的归属 |
|---|---:|---|
| `0x02000000..0x02400000` | 4MiB | 内核装载、静态工作区及保留范围；含代码、常量、任务栈、GIF 解码表、USB DMA 缓冲、字库初始化副本。部分为填充或未明确生命周期的间隙，不能直接当空闲池。 |
| `0x02400000..0x02500000` | 1MiB | 系统运行数据保留区；启动时实际复制约 0.960MiB，主要包含中文字库。 |
| `0x02500000..0x02700000` | 2MiB | 原生全局 malloc 堆，系统与下载程序共享。 |
| `0x02700000..0x02800000` | 1MiB | 当前下载程序的代码、常量、数据和 BSS；可在不重叠的自身区间内布置额外静态工作区。 |

字库本身很大：GB2312 12 点符号 20,304 字节、12 点汉字 162,432 字节、GBK 16 点字模 766,080 字节，三组共 948,816 字节（约 0.905MiB）。固件保留初始化镜像，又复制一份到运行地址，两份约 **1.81MiB**。实际 COM3 在各字库起点、中间和末尾抽查了 12 组 64 字节，包括 498 个非零源字节，初始化区与运行区全部一致。原生字形读取函数也明确访问这些运行地址。不能把这些副本或剩余填充区直接注册给 malloc：其后续初始化、音频和电源模式生命周期尚未全部证明。

本轮 2MiB 堆里已有 362,620 字节分给 62 个块，包含：

| 已分配部分 | 字节 | 依据 |
|---|---:|---|
| D88DEBUG 驻留块 | 136,720 | 原始分配地址 `0x02537634` 与任务 8 控制块一致，包含对齐余量。 |
| NAND/FTL 整块工作缓冲及两张映射表 | 139,264 | `0x02500000` 的 128KiB 块及两个 4KiB 表；原生 NAND 读改写代码、几何参数和真机指针一致。 |
| 四个原生 16KiB 块 | 65,536 | 真机分配目录确认；具体子系统用途未全部命名。 |
| 其余原生小块 | 21,100 | 分配目录统计；包含运行时对象，未将未知块强行归给某个子系统。 |

另有 520 字节分配目录、968 字节洞，以及尾部新增目录项的空间。因此当时最大连续请求为 1,733,036 字节，合计空闲 payload 为 1,734,004 字节。系统从未把全部 8MiB 暴露为同一个 malloc 池。

### 已在真机同时使用 2.25MiB

独立 D88MAP `8b456232` 保持系统堆边界不变，同时持有并验证：

- 原生 malloc **1.5MiB**：`0x02558C44..0x026D8C44`，仍保留 GUI 所需余量。
- 自身程序窗口中的 **768KiB** 静态区：`0x02740000..0x02800000`。
- 合计 **2,359,296 字节，即 2.25MiB**，分成两段使用。系统单次 malloc 上限没有因此改变。

两轮完整图案、逐字比对和 CRC32 全部通过（`fa684127`、`32911f49`）。静态区验证结束后再次完整检查 malloc 块，确认两块没有互相覆盖；释放后 19 字段堆快照和有效目录 CRC 完全恢复。实际 report 为 DONE、result=0、flags=63。该结果包含真实后台调试器共存，独立原生 QEMU 回归作为另外一项验证，不作为真机替代。

实现位于 `memory_layout/static_arena.c` 和 `memory_layout/link.ld`。静态数组放在独立 `.app_arena` 段，链接器检查程序文件及普通 BSS 不超过 `0x02740000`、arena 不超过 `0x02800000`。此段为 NOLOAD，不将 768KiB 填充塞入程序文件，运行时显式初始化全部内容。一般应用可以采用相同的自有静态区布局；代码/BSS 较大的程序应重新分配段边界并保留链接断言。这块内存只有当前前台下载程序的生命周期，不能把其中指针留给长期后台任务。

程序启动接口的文件头不带独立 BSS 或栈大小字段；原生加载器将 payload 读入固定 `0x02700000` 后调用该地址。GUI 任务栈实际在 `0x02018394` 附近，D88MAP 真机 SP 为 `0x02018154`，没有占用下载窗口尾部。新诊断通过已验证并备份的自有 D88MEM 文件名临时启动；完整运行被 finally 恢复流程包裹，结束后原程序 33,405 字节全文及 SHA256 均恢复为 `bbd2c8b0…35c71a5`。日志为本地 `slot-session.json`；系统内存和 IRAM 在此探测中均只读。

## IRAM 多大，普通程序能用多少

片内 IRAM 容量为 **16KiB**，位于 `0x00000000..0x00004000`，不包含在上表的外部 SDRAM 8MiB 内。它已有系统用途：

- 真机 `0x0100..0x30C7` 的 **12,232 字节**与启动时复制的系统代码/数据映像完全一致。
- `0x0004..0x0059` 的 **86 字节**与原生 idle/self-refresh 代码一致。
- 顶部有原生中断保存帧、栈和保留状态；两次快照变化的 **43 字节**全部位于 `0x3FA0..0x3FD7`，中断保存指针为 `0x3FD8`。音频和电源路径还会切换栈或覆盖部分低内存。

当前**已证明可由普通下载程序独占并安全分配的 IRAM 范围为 0 字节**。这是所有权结论，不是声称每个字节每时每刻都活跃。稳定、全零或未找到立即数引用，都不能证明中断、音频、省电路径不会使用它；最大栈深度也尚未证明。旧 SDK 声明的 `.iram 0x0800` 没有自动复制/预约机制，而且该地址落在当前系统映像内；不能直接把普通数组或热点函数链接过去。

本轮已完整只读采集 IRAM 两次，未向 IRAM 写入任何测试图案。普通程序可通过已核实的原生接口使用系统服务，暂不具备一个通用的应用 IRAM 分配器。更大内存的已验证做法是上面的 SDRAM 程序静态区。

布局探测的 44,172 字节报告位于本地 `captures/2026-11-05-layout-research/D88MAP.BIN`，CRC32 为 `a1f28846`，SHA256 为 `40a3d70c729ba192fa08ac66d0d4d9ed28a5e473174d3be730a07e6f908edac8`。报告、IRAM 双快照、128 个 SDRAM 页的只读统计、恢复日志及最终菜单截图均已保存。页中全零/FF 的统计只是顺序观察，不用于授予应用内存所有权。
